## 新增边界及兼容影响

- C2S Molang 表达式最多 8192 个 Java 字符；每连接每秒补充 20 次额度、最多突发 40 次。限速时只保留最新请求并由服务端 tick 补发，连续滑条拖动会同步最终值；超额的一次性脚本可能被合并。第三方实体控制须在恢复对应兼容实现时补明确的归属校验。
- 每个实体最多缓存 64 条网络表达式，满队列合并最后一项，每次动画处理批次最多执行 16 条（不是整帧的总配额）。普通本地表达式队列保持原有行为。
- Molang 顶层求值最多 100,000 步、嵌套深度最多 128；嵌套循环、函数实参和 arrow 子求值器共享预算。解析也限制深度。它会影响超出预算的复杂合法模型；超限会停止表达式，安全求值路径可能回退为 0。建议在代表性模型包上复验。
- 分片仍保持原有单包 2 MiB、单片 30,000 字节上限。每连接最多 4 个未完成传输/8 MiB，全局最多 128 个/64 MiB；每连接 16 MiB/s、允许 16 MiB 突发。空闲 30 秒或总寿命 60 秒后回收，tick 每秒最多扫描一次。慢链路、大量同时传输需要按此边界测试。
- Zstd 单次解压输出最多 256 MiB；流式内部回看窗口最多 8 MiB，块大小最多 128 KiB。超过上限的资源会被拒绝，而不是尝试无界分配。
- TOML 语法错误后 GUI 修改只在内存生效；修复原文件并重新启动后恢复持久化。日志会明确提示。

## 验证方法与范围

```sh
./gradlew clean build --no-daemon --console=plain
./gradlew runClient
```

JUnit 覆盖配置文件保护、渲染状态保活/回收、骑乘坐标、分片及速率配额、Molang 预算和 Zstd 往返/边界。输入、缓存、CCA 另有针对实际修复类的隔离行为验证；隔离验证使用 Minecraft/Fabric stub，不能视为游戏实测。正式测试代码位于 `src/test/java`，不替换生产 Minecraft 类。

本次本地结果（Windows / Java 25）：完整 clean build 通过，最终 build 的 32 项 JUnit 全部通过；隔离状态验证 29 项断言通过。真实 Fabric 客户端启动检查通过，在资源 overlay 消失后稳定运行 20 tick，实际 Options 中 8 个额外动画键及 5 个普通键各注册一次，并正常退出。启动界面为 AccessibilityOnboardingScreen，没有进入世界；临时检查模组未打入正式产物。构建仍有原有 Unsafe/弃用 API 与 ImageStream SNAPSHOT 版本警告。

需要游戏内复验：GUI 预览与鼠标旋转、BMP/JPEG 头像色彩、不同海拔骑乘、L 和额外动画键、GUI/失焦后的输入状态、旧存档完整升级、多人同步与典型模型包兼容。启动成功或单元测试通过都不能证明这些画面和联机行为已全部通过。

交叉审查还发现原有 `EntityJoinCallbackEvent` 待执行回调仅按 entityId 缓存，没有会话归属；快速换服时的 ID 重用需要另行处理。本次未修改这条额外路径。
